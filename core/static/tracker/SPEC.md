# SPEC каталога `core/static/tracker/`

## Фактический порядок подключения

`core/templates/tracker.html` подключает файлы в порядке: `boot.js` → `core.js` → `ui.js` → `task_card.js` → `tabs.js`. Это важнее алфавитного порядка: более поздние файлы используют globals и функции предыдущих.

Общего `TrackerApp` нет. Код использует IIFE и именованные `window`-экспорты/guard-флаги (`__trkState`, `__trkRefreshAll`, `__trkOpenTaskModal`, `__plan2027Render` и др.). Перед переименованием функции ищите все вызовы в пяти файлах.

## Файлы

| Файл | Ответственность и владельцы |
|---|---|
| `boot.js` | Ранние общие guard-флаги, признаки завершения/проблем и plugin/menu bootstrap. Должен выполняться до основного состояния. |
| `core.js` | Главное состояние tracker, `apiJson`, загрузка `/api/tracker/state`, базовые render/CRUD. `apiJson` использует same-origin credentials, `cache: no-store`, и добавляет `X-CSRF-Token` для не-GET. Это основной владелец сетевого CRUD. |
| `ui.js` | UI-поведение, фильтры, поиск, компактность, модальные окна, merge и hooks сохранения. Не дублировать в нём backend-правила. |
| `task_card.js` | Карточка задачи: ссылки, приказы, уведомления, открытие/редактирование из разных представлений. Использует state/API из `core.js`. |
| `tabs.js` | Навигация вкладок, Gantt, отсутствия, dashboards и независимый PATCH PLAN2027. Самый большой orchestration-файл; изменять scoped-блоками. |

## План 2027: отдельный контур

PATCH PLAN2027 в `tabs.js` не является копией Gantt heatmap API и не должен менять Sandbox. Контур:

`tracker.html` → кнопка `openPlan2027InlineBtn` → `tabs.js` → `/api/plugins/pockets/data?year=2027` + tracker state → группировка `direction|pocket` → lane render → `/api/tracker/task/save`.

- ПВР группируется сначала по направлению, поэтому `corp|ПВР` и `retail|ПВР` независимы.
- `selectedPocketKey` отвечает за выбранный summary/карман; `p27PocketFilterKey` — за нижнюю карту нагрузки. Не объединять эти состояния.
- Оси строятся по плану кармана; свободные оси пунктирные и показывают подсказку только при hover.
- Предварительные/не сохранённые проверки светлые и с пунктирной рамкой; утверждённые — со сплошной.
- Чипы банков/этапов по умолчанию скрыты; кнопка раскрытия относится к конкретной оси и сохраняет состояние при перерисовке.
- Общая и выбранного кармана тепловые карты считают distinct audit по пересечению дат банк×месяц. Нагрузка не складывает веса этапов.
- Переключаемые гистограммы используют старый взвешенный расчёт по всем карманам; нижняя heatmap — единственный pocket-specific вид.

## Изменение frontend

1. Найдите владельца функции и все `window`-экспорты.
2. Проверьте API route и формат state до изменения DOM.
3. Для Plan2027 не переиспользуйте без проверки селекторы Sandbox/Gantt.
4. После изменения: `node --check` всех затронутых JS, `git diff --check`, Chromium light/dark 1440/390, console/pageerror и геометрию lanes/heatmaps.
5. Не менять `tracker.html` так, чтобы нарушился порядок загрузки без проверки всех globals.
