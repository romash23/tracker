# Трекер задач

Локальный корпоративный трекер проверок, задач, календаря и планирования. Приложение запускается как standalone Flask-сервис с SQLite и работает в локальной сети без внешней облачной зависимости.

> Документация по структуре и взаимодействию файлов: [SPEC.md](SPEC.md). Для конкретных частей проекта: [core/SPEC.md](core/SPEC.md), [core/plugins/SPEC.md](core/plugins/SPEC.md), [core/static/SPEC.md](core/static/SPEC.md), [core/static/tracker/SPEC.md](core/static/tracker/SPEC.md), [core/templates/SPEC.md](core/templates/SPEC.md).

## Возможности

- календарь и отметки по сотрудникам;
- задачи и проверки с исполнителями, сроками, статусами и этапами;
- планирование проверок и визуальные временные шкалы;
- справочник банков, сотрудников, направлений и карманов;
- планы карманов по годам;
- **План 2027** с группировкой по направлению и карману, компактными осями и нагрузкой по месяцам/банкам;
- отчёты и сводки, включая недельный отчёт;
- экспорт данных в Excel;
- настройки тем, пользователей, ролей и разрешений;
- обновление клиентских файлов через JSON-патчи.

## Архитектура

```text
Browser
  └─ Jinja templates: core/templates/
       └─ static assets: core/static/ + core/static/tracker/
            └─ Flask routes: core/app.py + core/plugins/*.py
                 └─ HookRegistry / plugins_loader.py
                      └─ SQLite: core/db.py + core/schema.sql
```

Backend — Flask. Frontend — обычные JavaScript и CSS без обязательного SPA-фреймворка. Плагины регистрируют маршруты, хуки и иногда встроенные HTML/JS/CSS-ресурсы. Основное состояние трекера загружается через `/api/tracker/state`, изменения отправляются через API с CSRF-заголовком.

## Запуск

### Windows

Запустите `START.bat`. Скрипт вызывает `core/run.py`, читает [core/config.json](core/config.json), поднимает сервер и при включённой настройке открывает браузер.

### Вручную

Нужен Python с зависимостями из [core/requirements.txt](core/requirements.txt):

```bash
cd core
python run.py
```

По умолчанию сервис слушает `0.0.0.0:5431`. Путь к SQLite — `task_tracker.db` относительно каталога запуска, если он не изменён в конфигурации. Для установки зависимостей:

```bash
python -m pip install -r core/requirements.txt
```

## Права и безопасность

- Аутентификация и разрешения реализованы в `core/auth.py` и используются маршрутами приложения.
- Для изменяющих запросов применяется CSRF-токен: шаблон передаёт его в meta/global, а `core/static/tracker/core.js` добавляет `X-CSRF-Token`.
- Не коммитьте `task_tracker.db`, секреты и локальные конфиги. Файл `.env` и рабочая база не являются частью исходной поставки.
- Перед изменениями в API сначала проверьте цепочку: шаблон → JS → Flask route → DB → обратный рендер.

## Обновление патчами

Патчи хранятся в [core/patch_runs](core/patch_runs) как JSON-артефакты стадий применения. Общий механизм находится в [core/patcher.py](core/patcher.py). Перед применением используйте dry-run, если он поддерживается конкретным сценарием:

```bash
python core/patcher.py path/to/patch.json --dry
python core/patcher.py path/to/patch.json
```

Правила папок патчей описаны в [core/patch_runs/SPEC.md](core/patch_runs/SPEC.md).

## Разработка и проверка

1. Определите владельца изменения по SPEC в нужной папке.
2. Не редактируйте результат генерации вместо источника: для UI проверяйте `templates`, `static/tracker` и backend route вместе.
3. Для Python выполните `python -m py_compile <files>`, для JavaScript — `node --check <files>`.
4. Проверьте `git diff --check` и сценарий, затронутый изменением.
5. Для UI проверяйте светлую/тёмную тему и desktop/mobile; ошибки console/pageerror должны отсутствовать.
6. Не меняйте рабочую БД при тестировании — используйте копию.

## Структура

- `core/` — приложение, БД, плагины, шаблоны и статические ресурсы.
- `core/plugins/` — подключаемые backend-модули и встроенные plugin assets.
- `core/static/` — общие CSS/JS; `core/static/tracker/` — основной frontend трекера.
- `core/templates/` — Jinja-шаблоны страниц.
- `core/patch_runs/` — JSON-история/артефакты применения патчей.
- `START.bat` — запуск в Windows.

## Ограничения текущего состояния

Проверка выполняется на Chromium и локальной копии данных; production-развёртывание этим репозиторием автоматически не выполняется. Часть plugin JavaScript и HTML встроена в Python и не имеет отдельного файла в `static/` — это описано в [core/plugins/SPEC.md](core/plugins/SPEC.md).
